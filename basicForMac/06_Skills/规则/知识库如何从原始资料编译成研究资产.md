# 知识库如何从原始资料编译成研究资产

Karpathy 的核心思路不是把 Obsidian 当收藏夹，而是把知识库当成一个持续编译项目：原始资料进入 `raw/`，LLM 增量编译成 Markdown wiki，随后用问答、输出和健康检查反哺 wiki。对应到本库，就是把 `00_Inbox`、`01_Sources` 编译成 `02_Knowledge`、`03_Topics` 和 `04_Outputs`，并让每次研究和写作都留下可复用资产。

## 一、总循环

| 环节 | 本库位置 | 核心动作 |
| --- | --- | --- |
| 捕获 | `00_Inbox` | 收集论文、网页、知乎、公众号、灵感，只保留来源和原文摘要 |
| 存证 | `01_Sources` | 保存原始论文、报告、剪藏和数据，作为后续所有结论的证据层 |
| 编译 | `02_Knowledge`、`03_Topics` | 把原始资料提炼成概念卡、方法卡、模型案例和选题问题 |
| 问答 | 全库 + 本地文件搜索 | 让 AI 基于知识库回答复杂研究问题，而不是凭空泛谈 |
| 输出 | `04_Outputs` | 生成文章、报告、综述、讲稿或可视化，回链到证据和卡片 |
| 体检 | `05_Review` | 检查重复、缺口、矛盾、孤立卡片、失效链接和薄弱结论 |
| 回流 | `02_Knowledge`、`03_Topics`、`05_Review` | 把问答、纠错、未解决问题和新联系写回知识库 |

这七步是同一件事的循环：新的输入被编译，旧的卡片被问答暴露问题，输出被回链成资产，体检再决定下一步补什么。

## 二、知识库分层

### 证据层

`01_Sources` 只负责证明“这个说法来自哪里”。

- 论文保留 PDF、摘要、实验设置、数据集、结论、限制和 References。
- 剪藏保留原文链接、作者、日期和关键引文。
- 不直接在原始资料上做大面积改写。
- 每条资料都要能回答：它和生成式推荐中的哪个问题有关？

### 编译层

`02_Knowledge` 是给未来研究使用的中间表示，不是原文摘要堆。

- 概念卡回答：这是什么，为什么在生成式推荐里重要。
- 方法卡回答：怎么做，输入输出是什么，训练和推理成本如何。
- 模型与案例卡回答：具体系统怎么落地，效果和限制是什么。
- 工具卡回答：代码库、数据集或框架适合解决什么问题。

每张卡采用固定结构：一句话结论、证据来源、机制拆解、与本库其他概念的连接、适用边界、待验证问题。

### 研究层

`03_Topics` 负责把散卡组织成研究方向。

- 选题池放值得写成文章、综述或实验的主题。
- 研究专题放多个卡片和证据的聚合视图。
- 问题清单放当前知识库答不好、但值得继续追问的问题。

### 输出层

`04_Outputs` 不只是成果，也是一次知识库压力测试。

- 写作时先让 AI 列出引用卡片和原始资料。
- 如果一个段落找不到证据，就回溯到 `01_Sources` 或把它降级为推测。
- 输出定稿后，把它链接回相关卡片和专题，让写作结果也成为知识库入口。

## 三、LLM 编译规则

AI 负责增量编译，用户负责确认关键结论。

1. **先读来源，再写卡**：没有读到原文或可靠摘要时，只建候选卡，不写成定论。
2. **一卡一事**：一张卡只解释一个概念、方法、模型或问题。
3. **增量更新**：新资料只补充受影响卡片，不为了整齐而批量重写全库。
4. **结论分级**：区分“原文明确说明”“多处来源支持”“AI 推断”“待验证”。没有证据的判断不进入正式结论。
5. **保留反例和限制**：性能提升、数据集、评测方法、失败场景和工程成本都必须记录。
6. **真实连接优先**：只建立有研究含义的链接，不做装饰性反向链接。
7. **标签沿用索引**：优先复用 `生成式推荐`、`推荐系统`、`AI`、`语义ID` 等已有标签。
8. **统一 Obsidian 格式**：AI 新建或整理的 Markdown 默认按
   `/Users/yangxiaochun/Documents/obsidian/obsidian-skills/skills/obsidian-markdown/SKILL.md`
   处理 frontmatter、内部链接、外部链接、callout、表格和代码块；只改格式，不改证据和结论。

AI 生成的卡片初稿标注 `状态: 待确认`；用户确认核心结论后，才视作长期知识资产。批量合并、重命名或修改超过 10 个文件前，仍按本库安全规则先给出影响范围并等待确认。

## 四、索引层

为了让 AI 和人都能快速导航，知识库需要四类轻量索引，而不是一个巨型目录。

| 索引 | 位置 | 内容 |
| --- | --- | --- |
| 原始资料索引 | `01_Sources/论文报告/README.md` | 论文、主题、精读状态、核心贡献和待补全项 |
| 知识卡片索引 | `02_Knowledge/README.md` | 概念、方法、模型案例、工具及一句话作用 |
| 研究问题索引 | `03_Topics/README.md` | 当前问题、可用卡片、证据缺口、候选输出 |
| 输出索引 | `04_Outputs/README.md` | 正式产出、候选输出、引用要求、状态和回流动作 |

索引只放一句话摘要和链接。新资料进入后先更新索引，再决定是否需要新建或更新卡片。

## 五、问答反哺机制

每次向知识库提问，按四个结果处理：

| 结果 | 回流动作 |
| --- | --- |
| 答案已经存在 | 记录引用了哪些卡片，必要时补充更清晰的表达 |
| 答案散在多个卡片 | 更新研究专题，把这条路径沉淀下来 |
| 答案只在原始资料里 | 新建或升级知识卡片，让下次不用重读原文 |
| 知识库无法回答 | 写入 `03_Topics/问题清单`，标明缺失的资料或实验 |

这个规则的价值在于：研究过程中的临时探索不会消失，而是持续变成索引、卡片或问题。

## 六、健康检查

每周或每月做一次 LLM 体检，输出到 `05_Review/知识库优化记录`。检查项包括：

1. **证据完整性**：关键结论是否有来源，是否存在未被原文支持的说法。
2. **重复与冲突**：同一概念是否有多张卡，不同论文结论是否被清楚区分。
3. **孤立卡片**：是否缺少和概念、方法、模型或选题的真实连接。
4. **覆盖缺口**：生成式召回、语义 ID、生成式排序、评测、产业落地等主线是否缺关键资料。
5. **时效性**：旧结论是否被新论文替代，是否需要标注“历史方法”或“已被改进”。
6. **链接健康**：是否失效链接、附件丢失或索引和实际文件不一致。
7. **命名与标签**：标题是否表达核心观点，标签是否复用规范写法。
8. **问题价值**：问题清单里哪些问题已经能回答，哪些应该归档。

体检后给出三类动作：立即修复、需要用户确认的批量修改、下周补充资料计划。

## 七、节奏

| 频率 | 动作 |
| --- | --- |
| 每天 | 论文引文简报在 7:00 生成；如有新增抓取内容，快速判断是否进入 `01_Sources` 或归档 |
| 每周 | 清空 `00_Inbox`，编译本周新资料，更新四类索引，写周复盘 |
| 每月 | 做一次完整健康检查，更新研究专题、问题清单和下月重点 |
| 每季度 | 判断知识库主线是否漂移，归档低价值分支，确定下一阶段研究问题 |

## 八、度量

判断知识库是否真的在迭代，看五个信号：

- **输入转化率**：多少来源变成了卡片、专题或问题，而不是长期堆积。
- **证据密度**：正式结论是否都有可回溯来源。
- **复用率**：输出文章和报告是否频繁引用已有卡片。
- **问题闭环率**：问题清单中有多少问题被新资料或新卡回答。
- **研究推进度**：知识库能否解释当前领域的主线、分歧和未解决问题。

## 九、落地顺序

1. 建立四类索引，先给现有论文和卡片做一次基线盘点。
2. 给每张卡片补 `状态`、`证据强度`、`待验证问题` 和真实链接。
3. 选一个高价值专题做首次问答反哺，例如“生成式召回为什么能改善冷启动”。
4. 做首次知识库体检，记录重复、缺口、薄弱结论和批量修改建议。
5. 把体检中反复出现的问题固化为新的检查规则或技能。

本方案不是替换现有流转规则，而是给它加上 Karpathy 式的“编译、问答、体检、回流”机制：原始资料不断变成结构化资产，研究输出又不断反哺知识库。
