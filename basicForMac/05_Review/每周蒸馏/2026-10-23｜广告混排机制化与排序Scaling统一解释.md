# 2026-10-23｜广告混排机制化与排序Scaling统一解释

## 一句话蒸馏

10 月 18 日以来的本地资料把两条散落线索整理成了更清楚的研究对象：广告混排已经从「排序模型升级」推进到「全 feed 与全链路生成机制」，激励兼容从附加检查变成路线选择问题；排序骨干 Scaling 则从 RankMixer、TokenMixer-Large 到 UniMixer 形成一条可解释的演化轴，把硬件效率、规模化稳定性和可学习混合表达力放进同一框架。

## 主题提炼

### 1. 广告混排从局部排序器走向机制设计问题

1. **改变了什么理解**：广告混排的新证据不再只比较「哪个生成器效果更好」。CGA 把排列级外部性引入自回归拍卖，MIRT 把精确 DSIC 作为设计目标，NGA 和外卖列表方案关注非自回归延迟，EGA-V2 与 UniROM 进一步把分配、计费或全链路放进统一框架。由此，混排研究的核心变量变成三组选择：分配范围是广告列表、自然加广告全 feed，还是召回到创意全链路；外部性建模是 point-wise、set-level、排列级还是 whole-feed 级；计费走结构保证、遗憾最小化，还是旧计费结构加模型调控。
2. **支撑材料**：[[混排Re-Rank：影子出价把参与度约束转化为自然与广告流的统一排序货币]]、[[DNA：可微分排序让拍卖机制进入端到端学习]]、[[CGA：自回归生成式拍卖捕捉排列级外部性并解耦分配与支付]]、[[外卖列表广告生成式整体拍卖一期：用非自回归生成与RegretNet计费突破阶乘组合空间]]、[[MIRT：用maximal-in-range结构换取精确DSIC的whole-feed生成式拍卖]]、[[EGA-V2：把召回排序创意分配计费统一进单个生成模型的全链路广告框架]]、[[UniROM：广告排序的端到端统一生成架构]]、[[混排技术演进路线：从影子价格到全链路生成式拍卖]]。
3. **适用于什么边界**：CGA 的线上证据限定在淘宝 CPC 拍卖和 2% 流量实验；MIRT 只有合成环境和 hard attention 理论假设；NGA 证据强度受摘要与转述限制；EGA-V2 缺少线上部署证明。不同方案的流量、指标、出价参数和结算方式不同，收益数字不能组成同一张排行榜。精确 DSIC 也不等于长期广告主策略均衡已经解决。
4. **还缺什么证据**：缺少同一候选池、同一延迟预算和同一出价参数下「近似 IC」与「精确 DSIC」的效果、收入、广告主长期行为和工程成本对照；也缺少 MIRT 类结构保证从合成环境迁移到工业 feed 的证据。全链路生成还必须有可解释的失败归因、自然体验保护和回滚机制证据。

### 2. 排序骨干 Scaling 从工程分叉走向统一解释

1. **改变了什么理解**：RankMixer、TokenMixer-Large 和 UniMixer 可以按同一条演化轴阅读。RankMixer 用固定置换换硬件效率；TokenMixer-Large 在不更换混合算子的前提下解决深层稳定、MoE 稀疏化和大规模部署；UniMixer 把固定置换改写成可学习稀疏置换，并用统一框架解释 attention、TokenMixer 和 FM 三条路线。这样看，Scaling 不只是「模型更大」，而是在参数效率、FLOPs、MFU、深度稳定性和混合表达力之间重新分配算力。
2. **支撑材料**：[[RankMixer：token混合让推荐模型MFU提升十倍]]、[[TokenMixer-Large：七十亿参数在线排序模型]]、[[UniMixer：把TokenMixer参数化成可学习稀疏置换矩阵统一三种推荐Scaling路线]]、[[排序骨干Scaling三代演化：RankMixer确立范式、TokenMixer-Large推向7B、UniMixer统一理论与表达力回归]]、[[Scaling Law在工业推荐系统的落地路径]]。
3. **适用于什么边界**：三代结论来自不同公司、不同任务和不同预算。RankMixer 与 TokenMixer-Large 是字节内部演进，UniMixer 的对照在快手留存任务上完成；UniMixer 的参数效率优势目前没有证明能平移到 7B 级模型或 CTR/CVR 任务。UniMixer 论文虽提到可延伸到生成式推荐，但该迁移没有实验支持。
4. **还缺什么证据**：缺少固定 FLOPs、固定时延、固定显存和固定业务指标下的跨代对照；缺少可学习稀疏混合在自回归生成任务中的稳定性证据；也缺少 Sparse-Pertoken MoE、SiameseNorm 和 UniMixing 在同一业务中组合后的消融。

### 3. 召回侧的生成式目标与服务形态仍需分层

1. **改变了什么理解**：KuaiFormer 提醒「生成式目标」和「生成式服务」不是同一件事：它用 next-action prediction 训练多兴趣表示，但推理仍走 ANN 向量检索。GRank 则用 target-aware 蒸馏保持 MIPS 效率，再用轻量 cross-attention 重排，说明可以把生成式表达力放在训练监督和小候选集阶段，而不一定维护结构化索引。
2. **支撑材料**：[[KuaiFormer：用Next Action Prediction把工业召回变成实时多兴趣检索]]、[[GRank：无结构索引的目标感知生成式检索]]、[[2026-10-22｜论文引文简报：GRank]]、[[2026-10-23｜论文引文简报：OneMall]]。
3. **适用于什么边界**：KuaiFormer 是快手短视频召回的一周多场景 A/B 证据，GRank 的线上 A/B 也较短且未报告显著性。两者都依赖快手内部数据流和基础设施，不能直接说明目标感知生成召回在其他业务同样有效。
4. **还缺什么证据**：缺少固定候选预算、固定 P99 延迟和相同 embedding 更新频率下的 KuaiFormer、GRank、MERGE、TIGER 式索引和 OneMall 式生成召回对照；也缺少候选天花板、新 item 冷启动和索引维护成本的分层分析。

## 研究问题变化

- **升级**：[[生成式推荐待研究问题清单]] 中「交叉特征与端到端生成架构如何兼得」应扩展到广告机制场景。生成式排序不仅要保留交叉特征，还要让排列外部性、预算约束、支付规则和自然体验进入同一评价体系。
- **升级**：「无结构索引与动态结构化索引的适用规模边界在哪里」获得更细的对照材料。GRank 证明可以用 MIPS 加局部重排绕开树/图索引，KuaiFormer 证明表示式召回仍是低延迟基础设施的重要形态；两者与语义 ID 多步生成应分开比较。
- **新增**：广告混排需要独立研究「生成式分配在何种延迟预算下应选择精确 DSIC，而非遗憾最小化」。这个问题与生成模型容量有关，也与广告主可接受的真实扣费风险有关，不能由离线 regret 指标单独回答。
- **新增**：排序骨干 Scaling 应追问「可学习稀疏混合是否只在判别式排序有效」。UniMixer 的统一解释很有价值，但其生成式推荐迁移还没有证据。
- **部分回答**：「多场景统一模型的负迁移何时出现」由 OneMall 补充了电商内部线索：商品卡、短视频和直播的 GMV 增益不同，说明统一架构的收益按场景意图明确程度和动态性分化。不过它仍没有给出通用负迁移检测指标。
