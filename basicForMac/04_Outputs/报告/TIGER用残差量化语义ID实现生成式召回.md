# TIGER用残差量化语义ID实现生成式召回

## 一句话结论

TIGER 把召回拆成两道题：**先用商品内容给每件商品编一个有结构的短号码，再用用户行为学会猜下一个号码。** 请求到来时，模型逐位生成几个可能的号码，再查表找出对应商品。它生成的是已有商品的编号，不是商品本身。

> [!info] 证据边界
> 本卡由每日讲解整理，内容已确认。跑鞋、二维向量和概率均为教学示例，不是论文实验数据。DPO、前缀树约束是扩展思路，不是原论文默认配置。

## 证据来源

- [TIGER：Recommender Systems with Generative Retrieval](https://arxiv.org/html/2305.05065)：§3.1、图 3 讲残差量化与碰撞，§3.2 和 §4 讲推荐模型及实现，§4.3 和 §4.5 讲冷启动和无效 ID。
- [Autoregressive Image Generation using Residual Quantization](https://arxiv.org/abs/2203.01941)：残差量化与自回归建模的方法背景，应用领域为图像，不作为推荐收益证据。

## 先看全流程

| 阶段 | 输入 | 做什么 | 产出 |
| --- | --- | --- | --- |
| 离线编号码 | 商品标题、品牌、类目等内容 | 把每件商品压成几个 token；如有重号，加尾码区分 | 商品与完整语义 ID 的双向映射 |
| 离线学推荐 | 按时间排好的用户交互记录 + 上一步的映射 | 把前几件商品的号码当输入、下一件真实商品的号码当答案 | 能逐位预测下一商品号码的 Transformer |
| 在线取候选 | 当前用户可用的历史 + 已训练的 Transformer | 生成多个完整号码，查表找商品，过滤不存在的号码 | 供下游排序使用的召回候选 |

**两个离线阶段的依赖是单向的。** Transformer 要用第一阶段产出的 ID 当输入和标签；原论文不用推荐损失反过来更新码本。常规线上请求也不用重新读商品文案、运行 RQ-VAE，或用连续向量到全库做 ANN 检索。

## 第一步：给商品编号码

### 先读懂商品，再用三套码本逼近它

以一双缓震跑鞋 A 为例。论文实验把标题、价格、品牌、类目等拼成一句话，用预训练 Sentence-T5 得到 768 维内容向量 $\mathbf x$。RQ-VAE 用**另一个可训练的全连接编码器**把它压到 32 维：$\mathbf z=E(\mathbf x)$。网络宽度为 768 → 512 → 256 → 128 → 32，三个隐藏层用 ReLU。进入残差量化的是 $\mathbf z$，不是 Sentence-T5 直接输出的 $\mathbf x$。

**码本是一组可学习的“标准向量”，码字是其中的一条。** 论文用三套独立码本，每套有 256 条 32 维向量。第一套挑一条最像 $\mathbf z$ 的，第二套只补第一套没表达的部分，第三套再补一次。不是拿同一个原向量分别做三次最近邻。令初始残差 $\mathbf r_0=\mathbf z$，第 $l$ 级执行：

$$
c_l=\arg\min_k\|\mathbf r_{l-1}-\mathbf e_{l,k}\|_2^2,\qquad
\mathbf r_l=\mathbf r_{l-1}-\mathbf e_{l,c_l}
$$

### 手算一次：为什么跑鞋 A 的前三位是 `[12, 37, 8]`

为了能手算，把跑鞋 A 的 32 维向量简化成二维 $(2.7,1.2)$。假设各级最接近当前残差的码字如下：

| 级别 | 当前要表达的向量 | 最接近的码字（编号 → 向量） | 减完后还差多少 |
| --- | --- | --- | --- |
| 1 | $(2.7,1.2)$ | `12` → $(2,1)$ | $(0.7,0.2)$ |
| 2 | $(0.7,0.2)$ | `37` → $(0.6,0.2)$ | $(0.1,0)$ |
| 3 | $(0.1,0)$ | `8` → $(0.1,0)$ | $(0,0)$ |

例如第一级如果还有候选 $(3,0)$，它与输入的平方距离是 $1.53$，而 $(2,1)$ 的是 $0.53$，所以这一对比中选后者。每一级都是在自己的码本里比较，第二级比较的是 $(0.7,0.2)$，不再比较 $(2.7,1.2)$。

最终**存编号，重建时才加向量**：

$$
\text{量化编码}=(c_1,c_2,c_3),\qquad
\hat{\mathbf z}=\sum_{l=1}^{3}\mathbf e_{l,c_l}
$$

在例子里，$(2,1)+(0.6,0.2)+(0.1,0)=(2.7,1.2)$；实际不要求残差为零。粗到细说的是**先做主要近似，再逐级补误差**，并不是 `12` 代表鞋类、`37` 代表跑步、`8` 代表某个品牌。

### 码本里的向量从哪来？为什么相像的商品可能共用前缀？

论文用首个训练批次的 k-means 聚类中心初始化码本，以降低大量输入挤到少数码字上的风险。

> [!question]- 三套码本怎样用 k-means 初始化？
> [TIGER 原论文 §3.1 和 §4](https://arxiv.org/html/2305.05065)明确说明了首批聚类、用中心初始化，以及实验采用批大小 1024、每级 256 个 32 维码字。论文未给出逐级初始化伪代码；下面是按残差量化流程可实现的做法。
>
> **编码器从哪来？** 预训练的是上游 Sentence-T5；RQ-VAE 编码器是另一个可训练网络，不继承 Sentence-T5 的权重，也不是由 k-means 学出来的。论文没有交代它的具体权重初始化方式，也没有描述单独预训练。复现时可以先初始化这个网络，让首批数据做一次前向。此时网络还没训练好，但已经能输出 32 维向量，**而且这一步不需要码本**：码本在编码器下游。随后用这些输出找聚类中心，k-means 只初始化码本，不更新编码器。
>
> 1. **第 1 套：对原始潜向量聚类。** 用 RQ-VAE 编码器把首批商品变成 1024 个 32 维向量，做一次 k-means（$K=256$），把 256 个中心存入第一套码本。每个向量减去**自己最近的中心**，留下 1024 条一级残差。
> 2. **第 2 套：对全部一级残差聚类。** 把 1024 条一级残差放在一起，再做一次 k-means（$K=256$）。中心初始化第二套码本；每条残差再减去自己最近的二级码字，留下 1024 条二级残差。
> 3. **第 3 套：对全部二级残差聚类。** 再做一次 k-means（$K=256$），中心初始化第三套码本。三套码本各有 256 条 32 维向量，参数独立，但初始化顺序有依赖。
>
> **第二级不是在第一级的每个簇里分别聚类。** 同一级只聚类一次，因此来自不同一级簇的商品也能共用一个二级码字。
>
> **一维小例子（每级只聚两簇）：** 输入是 `[0, 2, 4, 6, 20, 22, 24, 26]`。一级中心取 `3` 和 `23`，两组减完各自的中心后都剩 `[-3, -1, 1, 3]`。把残差合起来聚，二级中心取 `-2` 和 `2`；减去最近中心后只剩 `-1` 或 `1`，作为三级的两个中心。比如 `22` 依次选 `23 → -2 → 1`，相加就是 `22`。
>
> k-means 只给码本一个起点；后续码本随 RQ-VAE 训练更新，不是每个批次都重跑 k-means。

训练时，把所选码字之和 $\hat{\mathbf z}$ 送进 RQ-VAE 的全连接解码器 $D$，得到 $\hat{\mathbf x}=D(\hat{\mathbf z})$。**重建目标是 Sentence-T5 原先输出的 768 维内容向量 $\mathbf x$**，不是商品文字或用户行为。这样训练编码器学会保留量化后仍可用于重建的信息；编码器、解码器和码本一起更新。用本卡记号表示：

$$
\mathcal L=\|\mathbf x-\hat{\mathbf x}\|_2^2+
\sum_{l=1}^{3}\left(\|\operatorname{sg}(\mathbf r_{l-1})-\mathbf e_{l,c_l}\|_2^2+
\lambda\|\mathbf r_{l-1}-\operatorname{sg}(\mathbf e_{l,c_l})\|_2^2\right)
$$

三项分别做三件事：**重建项**要求少丢内容信息；**码本项**把选中的码字拉向它要近似的残差；**commitment 项**让编码器输出形成的残差也朝已选码字靠拢。$\operatorname{sg}$ 表示对应一侧只作为目标、不接收该项梯度；$\lambda$ 是后一项的权重（论文实验为 0.25）。

> [!question]- 初始化以后，每个批次怎么训练？
> **每批重新选码，但不重新跑 k-means。** 前向时用当前编码器算向量，再用当前码本逐级选最近码字；选出的向量相加后交给解码器。反向时用上面的损失更新参数。比如某一级的残差是 `2.7`，选中的码字是 `2.0`：只看这一条样本，码本项让码字往 `2.7` 靠，commitment 项让残差往 `2.0` 靠。
>
> **离散选码不能直接求导。** [RQ-VAE 方法论文](https://arxiv.org/html/2203.01941)用直通估计（straight-through estimator）：前向仍用量化后的向量，反向则把重建梯度近似传给编码器，不对“选中第几号”求导。TIGER 给出了联合训练损失，但没有展开直通梯度的实现细节。
>
> 编码器和码本更新后，同一件商品再次前向时可能选到不同码字。**首批 k-means 的簇分配不是固定标签**；最终语义 ID 用训练完成后的编码器和码本生成，再交给推荐 Transformer 使用。

内容相近的商品，若在潜在空间落进同一个最近码字区域，就会选到相同首码。因为第一步减的是同一个向量，两者的残差仍然接近，下一步也可能选到同一个码字。量化边界两侧的相近商品也可能得到不同首码；前缀共享是可利用的结构，不是类目规则或购买偏好的保证。

### 为什么还要加第四位？

同一个三位组合可能对应不止一件商品。比如跑鞋 A 和另一个款式 A′ 都选了 `[12, 37, 8]`，论文做法是分别登记为 `[12, 37, 8, 0]` 和 `[12, 37, 8, 1]`；没碰撞也补 `0`，比如跑鞋 B 编成 `[12, 37, 9, 0]`。**第四位只负责在相同三位前缀下区分商品，不是第四次量化。** 编码完成后，保留的是完整 ID 映射；用于训练内容重建的 RQ-VAE 解码器不负责线上查商品。

## 第二步：用行为记录教模型猜号码

假设某用户按顺序交互了「跑步袜 → 跑步腰包 → 跑鞋 A」。把前两件作为历史，最后一件作为下一商品标签，就得到一条训练样本：

- **输入**：`[用户哈希 token] [9, 4, 6, 0] [15, 32, 6, 0]`。括号只是阅读分组，模型实际读的是展开后的 token 序列；相同数字在不同码位用不同 token。论文把原始用户 ID 哈希到 2,000 个用户 token 之一，放在历史前面。
- **目标**：`[12, 37, 8, 0]`。标签来自真实发生的下一次交互，不是从商品内容计算出的“推荐答案”；内容量化只是把这件商品换成可预测的编号。

用的是 T5X 实现的编码器—解码器 Transformer（论文实验各 4 层）。**推荐编码器**用自注意力读入整段历史，输出上下文表示；**推荐解码器**一边看当前目标前缀，一边通过交叉注意力读取历史，输出下一位 token 的概率。这两个模块不同于第一步压缩和重建内容向量的 RQ-VAE 编码器、解码器。

训练时用真实的上一位串成前缀（teacher forcing）：先教模型在历史 $H$ 下预测 `12`，再给真实前缀 `[12]` 教它预测 `37`，接着预测 `8`、`0`。这里 $H$ 表示送进编码器的用户 token 和历史：

$$
P_\theta(c_{1:4}\mid H)=\prod_{l=1}^{4}P_\theta(c_l\mid H,c_{<l}),\qquad
\mathcal L_{\mathrm{rec}}=-\sum_{l=1}^{4}\log P_\theta(c_l\mid H,c_{<l})
$$

一句话：**内容决定号码怎么编，行为数据用来学习在当前历史下该预测哪条路径。** 把每件商品当作一个独立 token，词表要随商品数增长；拆成四位后，论文实验中商品部分的词表只需 $4\times256=1024$ 个 token。同前缀的商品还能共享前几步的监督，直到出现分叉才要区分。

## 第三步：线上生成多个完整号码，再查商品

上线后没有标准答案，模型必须用**自己上一步生成的 token** 继续猜。对同一段历史，假设模型已经生成共同前缀 `[12, 37]`，接下来有两条路：

| 候选商品 | 完整号码 | 第三位条件概率 | 第四位取 `0` 的条件概率 | 乘积（省略相同的前缀概率） |
| --- | --- | --- | --- | --- |
| 跑鞋 A | `[12, 37, 8, 0]` | 0.60 | 0.55 | 0.33 |
| 跑鞋 B | `[12, 37, 9, 0]` | 0.40 | 0.95 | 0.38 |

只看第三位会选 `8`，但走完以后 B 的完整路径分数反而更高。**Beam search 每步保留若干条累计分数最高的前缀**，再继续展开；若两条路都被保留，就能比较完整路径。实现里可以累加对数概率，等价于连乘；beam 有限，仍可能提前剪掉好路径。

最后拿完整号码查表：`[12, 37, 9, 0]` 找到跑鞋 B；如果生成了目录里没有的 `[12, 37, 9, 7]`，就拿不到商品。原论文提出扩大 beam 后过滤无效 ID；生成时用前缀树限制到有效路径是另一种工程方案，并非原论文的默认解码流程。

## 适用边界

- **替换的是召回方式，不是取消商品目录。** 常见双塔召回是“算用户向量 → 在商品向量索引里找近邻”；TIGER 是“生成完整商品号码 → 查映射表”。词表较小不等于更快，逐位解码和 beam 都有推理成本。
- **能给新商品编号码，不等于模型会自动给它流量。** 论文 §4.3 的冷启动实验是在已有商品的召回路径上，用前三位匹配补入未见商品，并限制它们在候选中的占比；不是证明模型会直接生成新商品的完整号码。

## 与偏好训练和评估的连接

语义 ID 的完整序列对数概率可接入 DPO/GRPO，但这是扩展方案。评估应区分候选集内概率排序与真实解码召回，同时记录 Recall、NDCG、有效商品率、重复率与时延。

## 待验证问题与复习

- 如何同时改善编码重建和行为相关性？码本变动后，旧历史与模型参数如何保持一致？
- 相同首码字能证明同一人工类目吗？不能，它只表明选中了同级同一码字。
- 重建误差下降必然提高 Recall 吗？不能，内容压缩目标与行为预测目标不同。
