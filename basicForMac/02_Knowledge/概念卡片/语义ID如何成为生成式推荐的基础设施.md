# 语义ID如何成为生成式推荐的基础设施

## 为什么需要它

自回归生成要求 item 变成离散 token 序列。语义 ID（SID）把 item 映射为层级化离散码，替代原子化的 item ID，带来泛化、冷启动和知识保留能力。

## 技术路线谱系

- 通用语义 token：[[TRM：语义token取代itemID释放扩展潜力]]——语义 token 来自结构化稳定集合，天然抗 item 生灭。
- 业务感知 SID：[[GR4AD：广告生成式推荐的架构训练推理联合设计]]（广告业务信息）、[[OneMall：快手电商多场景统一生成式推荐]]（电商语义+业务关系）、[[OneLoc：地理感知的本地生活生成式推荐]]（地理信息进 SID）。
- 动态索引：[[MERGE：动态聚类的流式item索引范式]]——从零自适应建簇、动态监控占用、细到粗合并，应对 VQ 在偏斜非平稳分布上的失效。
- 跨内容统一空间：[[GPR：广告推荐的统一生成式预训练范式]]——广告与自然内容共享多层级语义 ID 空间。
- 稀疏-稠密混合：[[COBRA：稀疏ID引导稠密向量弥补生成式召回信息损失]]——先生成 semantic ID，再在 ID 条件下生成稠密向量；这是对纯离散 SID 的补充，不是所有 SID 路线的必然结论。

## 机制光谱

| 机制 | 核心表示 | 推理方式 | 主要优势 | 主要代价 | 代表证据 |
|---|---|---|---|---|---|
| 纯离散 semantic ID | item 表示为层级离散码 | 自回归生成 token 路径 | 解码空间可控、枚举效率高、支持泛化与冷启动 | RQ-VAE/量化损失细粒度信息；层级错误会传播 | [[TRM：语义token取代itemID释放扩展潜力]]、[[MERGE：动态聚类的流式item索引范式]] |
| 稠密向量外挂 | item 表示为连续向量，SID 可选作辅助 | ANN 检索或稠密相似度 | 细粒度表达强，能保留连续偏好信号 | 全库 ANN 成本高；若预训练后冻结，容易与推荐目标脱节 | LIGER 的 unifying generative/dense retrieval 思路；RecFormer 一类稠密文本表征 |
| 稀疏 ID 条件化稠密生成 | `(semantic ID, dense vector)` 级联 | 先 beam search 生成 ID，再按 ID 条件生成稠密向量并 ANN 检索 | 用 ID 收缩候选空间，又用稠密向量弥补量化损失 | 需要 Beam Search + ANN 的联合资源；证据仍以单篇工业论文为主 | [[COBRA：稀疏ID引导稠密向量弥补生成式召回信息损失]] |

## 已知痛点

- 语义漂移：早期高层 token 出错不可逆带偏生成（PROMISE 的出发点）。
- 偏斜与非平稳分布：热门 item 挤占码本（MERGE 的出发点）。
- SID 质量上限决定生成上限：tokenizer 是整条管线的地基。
- 纯离散量化会损失细粒度语义：这是 COBRA 提出稀疏 ID 条件化稠密生成的动机，但当前只是单篇论文证据，不能写成 SID 的普遍规律。
