## 输出写作规则

1. **先列引用，再动笔**：每个候选输出先列出要引用的知识卡片和原始 PDF；没有证据的段落只能标为 AI 推断或待验证。
2. **一稿一问题**：一篇文章只回答一个研究问题；如果写作中分岔出新的重要问题，就写入 `03_Topics/问题清单`，不要塞进同一篇。
3. **结论分级保留**：正文区分「多篇来源支持」「单篇原文明确支持」「AI 推断」「待验证」。正式报告不把单篇工业实验写成通用规律。
4. **限制必须入文**：凡是用来支撑结论的关键实验，都要保留场景、流量、周期、基线和边界条件。
5. **初稿显性标注**：AI 初稿放入对应子文件夹，文件名加 `｜初稿`；用户确认核心结论后才转为成稿。

## 定稿回流规则

| 输出中发现的情况 | 回流动作 |
| --- | --- |
| 多张卡片共同支撑了一个清晰结论 | 更新对应 `03_Topics` 专题，把这条论证路径沉淀下来 |
| 某张卡片表达不清或缺少关键限制 | 更新 `02_Knowledge` 卡片，并检查 `证据强度` 与 `待验证问题` |
| 论证需要但知识库缺少来源 | 在 `03_Topics/问题清单` 记录缺口和下一份资料 |
| 输出暴露出卡片矛盾或单篇证据被过度泛化 | 写入 `05_Review/知识库优化记录`，作为下轮体检修复项 |
| 输出中形成新的选题价值 | 加入 `03_Topics/README.md` 的候选输出或问题清单 |

## 状态定义

- **待启动**：已有选题和证据池，但还没有输出初稿。
- **初稿**：已经成文，但未经用户确认。
- **待确认**：结构完成，等待用户确认核心结论和表达。
- **成稿**：用户确认，可对外复用。
- **归档**：被新版本替代、不再维护或暂时停止推进。
