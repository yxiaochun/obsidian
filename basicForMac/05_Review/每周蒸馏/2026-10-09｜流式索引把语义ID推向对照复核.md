# 2026-10-09｜流式索引把语义ID推向对照复核

## 一句话蒸馏

最近 7 天唯一的新增复盘材料是 [[2026-10-09｜论文引文简报：MERGE 流式item索引]]，它没有提出新的定论，而是把 [[MERGE：动态聚类的流式item索引范式]] 的引用队列重新指向流式 VQ、生成式检索、可学习 item tokenization 和语义 ID 实践经验四类对照工作。本周的蒸馏价值因此不在新增结论，而在确认语义 ID 路线对比必须补上这些原始证据。

## 新增证据

- **MERGE 引文简报进入复盘层。** [[2026-10-09｜论文引文简报：MERGE 流式item索引]] 基于 [[2026ByteDance_MERGE.pdf]] 解析出 36 条 References 和 26 条近 5 年候选，并精选 StreamingVQ、Trinity、TIGER、Learnable Item Tokenization 与语义 ID 实践指南。证据强度为**待验证**：这些都是标题和摘要级线索，简报也明确缺少具体实验指标、聚类设置和在线结果。
- **MERGE 卡仍是主线证据，但不是本周新增证据。** [[MERGE：动态聚类的流式item索引范式]] 已支持“动态聚类更适合偏斜、非平稳流式 item 分布”，同时说明其部署路径是传统检索而非生成式检索。证据强度为**原文明确支持**，本篇蒸馏只用它界定引用候选的相关性。

## 主题提炼

### 1. 流式索引应作为语义 ID 路线对比中的独立对照轴

1. **改变了什么理解**：今天的新材料没有推翻已有判断，但把“动态索引 vs 固定 VQ”扩展成更完整的验证框架：StreamingVQ 代表工业流式 VQ 基线，Trinity 代表 VQ 层级兴趣建模，TIGER 代表生成式检索语义 ID，Learnable Item Tokenization 代表可学习 tokenization，实践指南则可能补充工程评估经验。[[语义ID技术路线对比]] 需要的不是把五者并列成同等证据，而是逐篇核对后判断哪条路线与 MERGE 可直接对照。
2. **支撑材料**：[[2026-10-09｜论文引文简报：MERGE 流式item索引]]、[[MERGE：动态聚类的流式item索引范式]]、[[语义ID技术路线对比]]。
3. **适用边界**：当前判断只适用于索引/tokenization 层的路线梳理，不能推广为生成式推荐收益结论。MERGE 的在线收益来自 ByteDance 传统检索管线，精选引文尚未核对原文，也还没有与 MERGE 建立同数据、同任务、同预算的对照。
4. **还缺什么证据**：需要逐篇获取 StreamingVQ、Trinity、TIGER、Learnable Item Tokenization 和语义 ID 实践指南原文，记录聚类方式、码本更新、层级结构、训练目标、评测数据集、生成式/判别式部署路径和成本指标。尤其要先确认 StreamingVQ 与 MERGE 是否存在可复用的定量对比。

## 研究问题变化

- **部分回答**：[[语义ID技术路线对比]] 已经有通用量化、业务感知编码、动态索引和稀疏-稠密混合的初步证据，但今天的新增线索说明“流式场景长期行为”仍缺一组经过原文核实的对照研究。
- **升级**：「SID 质量如何评估」应把候选索引路线按“固定 VQ、动态聚类、生成式检索语义 ID、可学习 tokenization”分开评估，而不是把所有 item indexing 方案压缩成同一路线。
- **保持开放**：MERGE 能否稳定进入生成式检索仍未回答。今天新增的 TIGER 和可学习 tokenization 线索只是让这个问题更具体，尚不能支持任何路线排序。
