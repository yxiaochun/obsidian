# 语义ID技术路线对比

## 切入点

SID 是生成式推荐的管线地基，各家的构建方式正在明显分化：通用 RQ-VAE 式量化（TRM）、业务感知编码（UA-SID/OneMall/OneLoc）、动态自适应索引（MERGE）。

## 研究问题

- 动态索引（MERGE）与静态量化码本在流式场景的长期行为差异？
- 业务信息进入 SID 的最优粒度和时机？
- SID 质量如何离线评估？

## 证据强度评估

总体强度：中。已有证据能说明 SID 是生成式推荐的关键基础设施，且通用语义 token、业务感知 SID 和动态索引各有真实工业案例；但路线选择缺少统一离线指标和长期流式对比。

| 结论 | 证据强度 | 判断 |
| --- | --- | --- |
| SID 能替代原子 item ID，提供泛化、冷启动和知识保留能力 | 多篇来源支持 | [[语义ID如何成为生成式推荐的基础设施]] 汇总了 TRM、GR4AD、OneMall、OneLoc、MERGE 和 GPR 的共同动机；适合方向判断。 |
| 语义 token + 混合记忆 token 能改善排序模型 scaling | 原文明确支持 | [[TRM：语义token取代itemID释放扩展潜力]] 有大规模搜索离线对比、线上 A/B 和人工评估；但 mem-token 收益在约 2000 万附近趋饱和。 |
| 业务字段进入 SID 可以区分同一素材的不同投放目标 | 原文明确支持 | [[GR4AD：广告生成式推荐的架构训练推理联合设计]] 用统一广告语义 ID、共现学习和多粒度量化完成生产部署；哈希业务字段的跨平台迁移性是限制。 |
| 动态聚类更适合偏斜、非平稳的流式 item 分布 | 原文明确支持 | [[MERGE：动态聚类的流式item索引范式]] 报告索引质量和一周 A/B 收益；但当前部署仍在传统检索路径，尚未进入生成式检索。 |
| PRM 可降低层级 SID 的中间路径语义漂移 | 原文明确支持 | [[PROMISE：过程奖励模型解锁推荐推理时扩展]] 对每层路径打分并做逐步过滤；收益可能随层级数、item 空间和分布变化。 |
| 通用量化、业务感知编码、动态索引的适用规模边界 | 待验证 | 缺少同一 tokenizer 质量、同一下游生成任务和同一业务指标下的横向比较。 |
