# 广告混排方案对比：外部性建模、生成范式与计费机制的路线分化

## 一句话总结

到餐与外卖广告混排的六篇文档串出完整演进：从「DNA 端到端拍卖」到「NeuralAuction 序列生成」再到「生成式整体混排」，分化出**可微端到端排序、自回归生成 + DPO、非自回归分配矩阵**三条生成范式，配 **NeuralAuction / AMA / RegretNet** 三代计费机制；范式选择由**浮动位数量（组合空间大小）和性能预算**决定，而**收益结构（扩量驱动 vs 效率驱动）暴露了各方案的真实改进来源**。

## 维度一：自然候选如何进入机制

这是各方案最本质的分歧，本质是在回答「混排到底是广告问题的扩展还是独立的分配问题」：

- **不参与**：DNA 和两篇 NeuralAuction 是纯广告内重排，自然序列是固定环境；
- **零出价广告统一排序**（gDNA、外卖列表）：把自然视为 bid=0 的候选，让拍卖机制直接吃下混排。代价是分数空间问题——gDNA 要做二阶多项式保序映射 + MSE loss 对齐广告/自然分数（归因口径 CVR 分差达 2 倍）；外卖列表用「分配矩阵第 n+1 列放自然 score」的结构设计让自然自动保序，规避显式对齐；
- **只决策广告插入位次**（外卖搜索）：自然由后链路插入，生成器通过保序采样拿到准确的自然上下文——用架构边界换取简化；
- **作为上下文特征**（Listwise 评估器、LLM 文本校准）：自然不参与分配但参与外部性感知，这条线独立演进出「校准质量」这一共同瓶颈。

## 维度二：生成范式与优化方法

| 范式 | 代表 | 外部性建模 | 优化方法 | 优点 | 代价 |
| --- | --- | --- | --- | --- | --- |
| 可微端到端排序 | DNA、多位次 NA、gDNA | set encoder 集合粒度（+gDNA 的 posBias/listwise 层） | neural sort 松弛，loss 直接定义在分配矩阵上 | 训练直接、推理一次成型、耗时最低（gDNA 反降 10ms） | 集合粒度外部性看不到最终整页；IC 依赖网络结构假设（min-max 单调） |
| 自回归生成 | 外卖搜索一期 | transformer decoder 逐位次，天然感知前序排列 | 预训练（交叉熵）+ beam search 采样 + DPO 偏好对齐 | 外部性建模最完整；DPO 用相对偏好绕开 reward 绝对值不稳 | 耗时最高（+9.7ms）；对应 [[CGA：自回归生成式拍卖捕捉排列级外部性并解耦分配与支付]] 的工业化版本 |
| 非自回归分配矩阵 | 外卖列表一期 | self-attention 集合粒度 + 逐位次 mask 解码对齐业务约束 | 策略梯度 + Listwise 排列级 Reward（后验曝光加权） | 一次输出整页、推理效率高；mask 约束保证离线/线上一致 | 单序列 PG 方差大（下一步 GRPO）；reward 依赖评估器准度 |

值得注意的收敛信号：三篇一期方案的下一步指向同一处——**从单序列优化走向多样本组内优化**（外卖列表明确提 GRPO，外卖搜索的 DPO 本质是组内对比，gDNA 的线上多路扰动是推理时的朴素版本）。

## 维度三：计费与激励兼容

计费是演进最滞后的环节，三代机制并存：

- **NeuralAuction（GSP 约束 + 序特征调控）**：到餐两篇的方案，rankScore 网络在广义二价约束下学习排序与计费，价格杠杆和最小扣费靠结构保护；gDNA 和外卖搜索一期都**沿用**它——生成升级了、计费没跟上；
- **AMA 组合拍卖（被替换的基线）**：外卖列表基线用 top4 全排列 + AMA 计费，两个 IC 缺陷被明确诊断：top4 用 AMA、非 top4 用 GSP 导致同一序列计费模式不一致；耗时截断导致组合空间不完整；
- **RegretNet（遗憾最小化）**：外卖列表的答案——增广拉格朗日最小化事后后悔，以 IC 为直接优化目标，对胜出序列统一模型计费，离线 IC 指标 -30%，价格杠杆线上扰动验证持平（+0.48%）。与 DNA 的 min-max 结构性单调是「学习型拍卖保 IC」的两条技术路线：约束优化 vs 结构保证。

结构性观察：**分配的生成化和计费的生成化是解耦推进的**。只有外卖列表把两者放进同一框架（生成器冻结后训 RegretNet），其余方案都是「新分配 + 旧计费」；分配与计费联合端到端是明显空白。

## 维度四：效果结构与归因

| 方案 | 核心指标 | 收益结构 | 代价 |
| --- | --- | --- | --- |
| 多位次 NA | RPS+2.45%，日耗+9.4万（预估） | 计费调控（计价比+2.04%） | 密度-0.61% |
| gDNA | RPS+3.44%，CTR+2.46%，12.07万/天 | 扩量驱动（曝光+1.89%，位次 30→33 后移） | CVR-2.16%，ACP-0.77% 未归因 |
| 外卖搜索自回归 | 收入+0.96%，8.8万/天 | 扩量驱动（曝光+1.47%，兑换比约 1:4） | 耗时+9.7ms |
| 外卖列表非自回归 | 收入+3.22%，CPM+4.29%，51万/天 | **纯效率驱动**（曝光-1.03% 下收入增长） | 自然侧指标未报告 |
| LLM 文本校准 | 收入+1.04%，10.4万/天 | 排序质量（缩曝光 -0.44% 反证收入仍 +0.61%） | ROI-0.36% 稀释 |

外卖列表是唯一敢在曝光收缩下拿收入增长的方案，且做了扩曝光对照实验排除「位置红利」解释——六篇中归因最干净。反过来看，gDNA 和外卖搜索的收益中多大比例是「脱离模版后的扩量」而非「分配更优」，原文未做同等严格对照，跨方案比较需打折。

## 路线选择的决策逻辑

从六个案例反推，范式选择不取决于算法优劣，而取决于三个场景参数：

1. **浮动位数量（组合空间）**：到餐筛选拟合少量模版，gDNA 的 rankscore 排序可行；外卖列表 20 个浮动位、阶乘空间，必须非自回归 + 约束解码；外卖搜索居中，自回归可承受；
2. **性能预算**：到餐 gDNA 替换掉多位次 NA 反而省 10ms——性能不是硬约束时可选重方案；外卖搜索接受 +9.7ms 已接近极限；长序列场景自回归先出局；
3. **机制成熟度**：列表场景已有 AMA 组合拍卖基础和「首位求交」简化，才能直接跳到 RegretNet；搜索场景激励问题被求交逻辑部分屏蔽，一期不碰计费。

## 与影子价格选题的连接

[[混排影子价格的自适应路线与三层控制架构]] 从控制论视角把 NeuralAuction 定位为「决策规则可微化」路线、把生成式策略列为感知层 C 档——本对比为该框架补充工业落地证据：外卖列表的 listReward（后验曝光加权）是 B 档「条件效用估计」进入 reward 的实例；RegretNet 计费与「支付可进模型」的 C 档押注直接相关；「分配与计费未联合端到端」则对应其对 C 档「误差归属被污染」的担忧。生成式混排要接管决策权，IC 与守恒问题是两条线共同的前置。

## 尚未解决的共性问题

四个横跨所有方案、可作后续选题的开放问题：

1. **自然体验损失建模普遍粗糙**：gDNA 用固定位参数 penaltyScore、外卖列表用线性 k·imp 惩罚、多位次 NA 靠模版约束——没有一篇有真正的排列级自然体验模型，而每篇的 ROI 都因此存在未解释的稀释；拉格朗日框架（[[混排Re-Rank：影子出价把参与度约束转化为自然与广告流的统一排序货币]]）的显式约束恰好是对症的补法；
2. **校准质量是共同瓶颈**：gDNA 因预估分布 diff 放弃 listwise 校准、外卖搜索的 listReward 依赖校准 ctr、LLM 文本建模单独成篇——「评估器/校准器更准」可能是比「生成器更强」杠杆更高的方向；
3. **分配与计费未联合端到端**：RegretNet 需冻结生成器后单独训练，两阶段目标一致性未验证；
4. **特征范式升级是共同下一步**：Semantic ID（文本量化为离散 token）和用户行为序列同时出现在外卖列表与 LLM 文本建模的下一步计划中，指向「生成式混排 × 生成式表征」的下一阶段，与 [[语义ID技术路线对比]] 直接衔接。

## 附录：GRPO 在外卖列表方案中的移植设计

外卖列表一期自述的痛点是单序列 policy gradient 方差大（每请求只采一条序列、无 baseline、评估器噪声 1:1 进入梯度）。GRPO（Group Relative Policy Optimization）的移植几乎是逐项替换：

| GRPO in LLM | 外卖列表混排 |
| --- | --- |
| 同一 prompt 采 G 个回答 | 同一请求用 gumbel-softmax 采 G 条混排序列（mask 约束天然满足） |
| Reward Model 打分 | Listwise 评估器算 listctr → 组装 Reward_t（含 γ 折扣与 k·imp 惩罚） |
| 组内归一化优势 | 同一请求内 G 条序列的 reward 组内标准化，baseline = 组均值 |
| 去掉 critic | 不引入价值网络，评估器继续当 reward model |

Loss 从 $L=-\sum_t Reward_t \cdot Prob_t$ 变为 $L=-\sum_{i=1}^{G}\sum_{t} A_i \cdot Prob_t^{(i)}$，其中 $A_i$ 为组内标准化优势；也可对每个 slot t 在组内逐位次归一化（类似 per-token advantage），保留「当前步 + 未来折扣」的时间结构。

四个业务特有的设计点：

1. **组内基线顺带解决跨请求 reward 尺度问题**：一期用 gate 子网络应对多场景分数分布不一致，GRPO 的组内标准化让优势只依赖同请求内相对好坏，bid/pCvr 跨请求尺度差异被自动消掉——这是它比全局 baseline 更适合混排的原因；
2. **无信号请求自动零梯度**：G 条序列 reward 相同时优势为 0，训练预算自动集中到组内有分化的请求（通常是 mask 约束松、浮动位多的难请求）；
3. **防 reward hacking 评估器**：若 Listwise 评估器对某模式系统性高估，组内相对优化会放大该偏差（「校准质量是共同瓶颈」会被 GRPO 加剧）；对策是加 KL 锚——对旧策略或对显式分数先验 $A_{t,j}=M_{tj}+bid_j\cdot ctr_j+cvrk\cdot ctr_j\cdot cvr_j$（本身即良好先验）加 KL 惩罚；
4. **与 RegretNet 的两阶段纪律必须保持**：GRPO 改变生成器策略分布 → 冻结期训出的计费模型不再匹配新分布；每次 GRPO 迭代后需重训计费或严格保持「生成器收敛后冻结再训计费」的顺序。

与另两条路线的对照：gDNA 的线上多路扰动是推理时 best-of-N（不回传梯度），GRPO 是把组内比较变成训练信号的版本；外卖搜索的 DPO 是 GRPO 的二值化特例（成对偏好 = 组内最高/最低），但 DPO 需偏好标签、GRPO 直接吃评估器连续 reward，对混排场景 GRPO 更自然；CGA 的 Generator 同为单序列 REINFORCE，同样的 GRPO 升级完全适用。「非自回归生成 + 组相对优化 + RegretNet」的完整组合在公开文献中尚无先例，可作为外卖列表二期的论文级差异点。

> 外卖列表一期原文仅明确「采样多条序列做组内策略优化（GRPO 思路）减小方差」一句，上表映射、四个设计点与路线对照均为本人推断，非原文内容；KL 锚、逐位次归一化等具体做法未经验证。

## 附录二：DPO 能否替代 GRPO——两者差异与选型判据

两篇一期的选择（搜索 DPO vs 列表 PG→GRPO）看似路线分歧，实为同一判断标准下的两种结果：**标量 reward 是否可信**。通用机制差异见 [[DPO离线与GRPO在线：机制差异与生成式推荐中的选型]]，本节只写混排场景的特有判断。

### 机制差异的混排语境版

| | DPO（外卖搜索一期） | GRPO（外卖列表下一步） |
| --- | --- | --- |
| 学习信号 | 成对偏好标签 | 标量 reward（Listwise 评估器） |
| 数据来源 | 离线日志，off-policy | 当前策略采样，on-policy |
| 探索能力 | 无——只从给定 pair 学 | 有——G 条序列覆盖未曝光分配 |
| 信息利用率 | 只用 pair 内序关系，丢幅度 | 满用 G 条标量值（G=8 即 28 个 pair 的信息） |
| 训练成本 | 低，直接吃历史日志 | 高，每迭代 G× 评估器推理 |

形式化关系：DPO 可视为 GRPO 的退化特例（G=2、奖励二值化、REINFORCE 换成 log-sigmoid 似然比目标）。「DPO 能否达到 GRPO 的目的」的准确问法是：丢掉 on-policy 采样、幅度信息、G>2 组结构后还剩多少优化能力。

### DPO 在外卖列表场景的三个硬伤

1. **曝光偏差锁死探索空间（决定性）**：生成式混排的价值在于探索从未曝光过的分配序列，而日志只能提供「实际曝光过」的序列对——用离线 DPO 等于把生成器拉回模版路线的覆盖范围；主动采样构造 pair 则已经在做 on-policy 采样，与 GRPO 只剩目标函数形式之差；
2. **幅度信息全部丢弃**：评估器输出连续 listctr，好 0.1% 与好 30% 对 DPO 是同一梯度方向——评估器校准越准，丢幅度越可惜，这与「校准质量是共同瓶颈」互为表里；
3. **概率侵蚀与 β 工程债**：DPO 只保证似然比上升，迭代训练会同时压低两类样本的绝对似然、熵收缩，对 gumbel-softmax 非自回归结构是额外稳定性负担。

### 选型判据：reward 可信度一个维度定夺

- **评估器可信**（外卖列表：AUC 验证 + 价格杠杆扰动证据）→ GRPO 严格更优：满信息、on-policy、可探索未曝光空间，且是 PG 管线的 in-place 升级（采样 1 条 → G 条，其余不动）；
- **reward 绝对值漂移**（外卖搜索自述状态）→ DPO 的相对偏好对全局尺度偏差免疫，是更鲁棒的起点；组内标准化其实也自带此能力，但 reward 噪声大到组内排序不可信时，log-sigmoid 目标对异常值更忍耐。

因此两篇一期的差异不是团队品味，而是**两个场景评估器成熟度不同**：搜索的 listReward 依赖校准 ctr（尚在补课），列表已有验证过的评估器。

### 一个反向论点与终局形态

DPO 有 GRPO 没有的优势：**真实用户反馈可直接成为训练信号**（跨请求倾向性数据、干预实验的曝光对），而 GRPO 的 reward 永远是评估器 proxy——on-policy 采样再好，优化的也是代理模型。终局可能是混合：GRPO 用评估器做主优化信号（负责探索），DPO 类目标用真实反馈做校准修正（负责对齐真实分布）。
