# 2026-09-25｜缩放规律验证与稀疏稠密混合召回

## 一句话蒸馏

本周最大的推进是把上周仍留在 References 队列里的 HSTU 和 Wukong 升级成待复核论文卡，使推荐缩放规律从单一叙事拆成「生成式序列转导」与「稠密特征交互」两条可对比路线；同时 COBRA 把语义 ID 讨论推进到稀疏 ID 条件化稠密向量生成。

## 新增证据

- **HSTU 已从关键前序资料进入编译层。** [[Actions speak louder than words Trillion-parameter sequential transducers for ge.pdf|HSTU PDF]] 对应 [[生成式推荐：用万亿参数序列转换器 HSTU 替代 DLRM，验证推荐领域的缩放定律]]，卡片记录了生成式推荐范式、序列转换任务、工业 A/B 和跨三个数量级的算力缩放观察。证据强度为**原文明确支持**，但卡片状态仍是**待复核**，且低算力区间可能不如 DLRM。
- **Wukong 补上稠密特征交互路线的缩放证据。** [[Wukong Towards a scaling law for large-scale recommendation.pdf|Wukong PDF]] 对应 [[堆叠因子分解机实现推荐系统缩放定律：Wukong 在 100+ GFLOPexample 下持续提升质量]]，卡片记录了堆叠因子分解机、密集缩放策略、公开数据集与内部 146B 样本实验。证据强度为**原文明确支持**，但尚未触及缩放极限，不能与 HSTU 直接互换结论。
- **MTGenRec 把训练系统变成生成式推荐扩展的前置证据。** [[MTGRBoost Boosting Large-scale Generative Recommendation Models in Meituan.pdf|MTGenRec PDF]] 对应 [[MTGenRec：面向美团生成式推荐模型的高效分布式训练系统——动态哈希嵌入表、两阶段ID去重与动态序列批处理]]，说明动态嵌入表、两阶段 ID 去重和动态序列批处理共同支撑训练吞吐与线上效果。证据强度为**原文明确支持**，但基线只有 TorchRec，线上 A/B 也集中在美团外卖。
- **COBRA 提出稀疏 ID 条件化稠密向量生成。** [[Sparse Meets Dense Unified Generative Recommendations with Cascaded Sparse-Dense.pdf|COBRA PDF]] 对应 [[COBRA：稀疏ID引导稠密向量弥补生成式召回信息损失]]，先用 semantic ID 收缩候选空间，再生成端到端稠密向量，并用 BeamFusion 融合分数。证据强度为**单篇论文证据**；公开数据、工业离线和线上 A/B 方向一致，但缺少 LIGER 直接对照，工业消融还改变了 ID 粒度。
- **Hiformer、DeepSeekMoE 与每日引文简报提供外围方法参照。** [[Hiformer Heterogeneous Feature Interactions Learning with Transformers for Recom.pdf|Hiformer PDF]] 对应 [[Hiformer：用异构注意力与低秩剪枝实现工业级特征交互建模]]，支持异构特征交互与低秩近似的价值；[[DeepSeekMoE Towards Ultimate Expert Specialization in Mixture-of-Experts Languag.pdf|DeepSeekMoE PDF]] 对应 [[DeepSeekMoE：细粒度专家分割与共享专家隔离实现极致专家专业化]]，提供 MoE 专业化策略。两项证据强度均为**原文明确支持**，但前者是排序特征交互，后者是语言模型，不能直接写成生成式推荐通用结论。
- **本周引文网络显示 TIGER、HSTU、OneRec 和 Wukong 是高频交汇点。** [[2026-09-18｜论文引文简报：RankMixer]]、[[2026-09-19｜论文引文简报：OxygenREC]]、[[2026-09-20｜论文引文简报：OneLoc]]、[[2026-09-21｜论文引文简报：OneRec]]、[[2026-09-22｜论文引文简报：HoMer]]、[[2026-09-23｜论文引文简报：MTGR]]、[[2026-09-24｜论文引文简报：MTmixAtt]] 和 [[2026-09-25｜论文引文简报：UniROM]] 反复把基础架构、生成式检索、工业系统和扩展规律连接起来。证据强度为**多篇来源支持**，但多数候选文献仍只有摘要级线索。
- 本周没有新增 `00_Inbox`、`03_Topics` 或 `04_Outputs` 实质内容；主要变化集中在 `01_Sources/论文报告/ReferencesPDF`、对应论文卡和每日引文简报。

## 主题提炼

### 1. 缩放规律进入双轨验证阶段

1. **改变了什么理解**：上周的缩放规律讨论更接近「推荐模型可以 scaling」的抽象判断；本周 HSTU 和 Wukong 原文卡补齐后，证据显示至少存在两条路线。HSTU 把异构特征统一成序列转导任务，靠生成式架构、随机长度和推理摊销扩展；Wukong 则保留稠密特征交互，用堆叠因子分解机和密集缩放策略延长质量曲线。二者不能被压缩成同一个 scaling law 结论。
2. **支撑材料**：[[生成式推荐：用万亿参数序列转换器 HSTU 替代 DLRM，验证推荐领域的缩放定律]]、[[堆叠因子分解机实现推荐系统缩放定律：Wukong 在 100+ GFLOPexample 下持续提升质量]]、[[MTGenRec：面向美团生成式推荐模型的高效分布式训练系统——动态哈希嵌入表、两阶段ID去重与动态序列批处理]]、[[RankMixer：token混合让推荐模型MFU提升十倍]]、[[TokenMixer-Large：七十亿参数在线排序模型]]。
3. **适用边界**：HSTU 的工业证据来自大型互联网平台流式场景，论文也提示低算力区间可能不如 DLRM；Wukong 的优势主要在稠密特征交互和 CTR/CTCVR 类任务，尚未达到缩放极限。MTGenRec 只与 TorchRec 对比，且主要服务美团外卖。三者的数据、目标、硬件、序列长度和特征空间不同。
4. **还缺什么证据**：缺少同一业务目标、同一特征集、同一硬件和同一训练预算下的 HSTU、Wukong、RankMixer、TokenMixer 对照；也缺少训练吞吐、嵌入规模、推理 QPS 和长期在线收益的共同成本口径。

### 2. 语义 ID 从纯离散 token 走向稀疏-稠密混合

1. **改变了什么理解**：[[语义ID如何成为生成式推荐的基础设施]] 已强调 semantic ID 是生成式召回地基，但 COBRA 进一步说明纯离散量化会损失细粒度信息。它不把稠密向量当静态外挂，而是让稀疏 ID 先生成、再条件化稠密向量，使候选空间收缩和细粒度检索发生在同一条生成路径里。这把「semantic ID 替代 itemID」的问题扩展成「离散可枚举性与连续细粒度表征如何协同」。
2. **支撑材料**：[[COBRA：稀疏ID引导稠密向量弥补生成式召回信息损失]]、[[TRM：语义token取代itemID释放扩展潜力]]、[[MERGE：动态聚类的流式item索引范式]]、[[LEMUR：端到端多模态推荐替代两阶段表征]]。多篇资料支持混合表征和减少两阶段信息损失的动机；COBRA 的具体条件化稠密生成机制仍是**单篇论文证据**。
3. **适用边界**：COBRA 的公开数据集是 Amazon 三个短序列子集，工业证据来自百度广告召回和 10% 流量 A/B。它的线上结论不能直接迁移到视频、电商或本地生活场景；BeamFusion 参数、候选规模、ANN 索引和延迟也未充分披露。
4. **还缺什么证据**：需要在相同稠密编码器容量、相同训练预算和相同检索资源下加入 TIGER、LIGER、RecFormer 对照；工业消融要在同一 semantic ID 粒度下重做，并补充冷启动、多样性和 p99 延迟分层。

### 3. 训练系统成为生成式扩展的工程底座

1. **改变了什么理解**：上周报告 [[推理成本如何约束生成式推荐扩展]] 把推理预算作为主要约束；MTGenRec 说明训练侧同样会限制 scaling。动态哈希嵌入表处理实时插入和删除，两阶段 ID 去重降低查表通信，动态序列批处理缓解变长用户序列导致的 GPU 负载不均。生成式推荐的扩展问题因此要从「模型质量曲线」扩展到「训练系统、嵌入治理和推理服务」的联合系统问题。
2. **支撑材料**：[[MTGenRec：面向美团生成式推荐模型的高效分布式训练系统——动态哈希嵌入表、两阶段ID去重与动态序列批处理]]、[[生成式推荐：用万亿参数序列转换器 HSTU 替代 DLRM，验证推荐领域的缩放定律]]、[[SORT：面向工业规模的排序Transformer系统优化]]、[[TAE：基础模型加专家范式的超规模部署]]。
3. **适用边界**：MTGenRec 的 GRM 基于 HSTU，但训练系统证据集中在 TorchRec、美团外卖和 100+ GPU 配置；动态嵌入表长期运行中的内存碎片、哈希冲突和删除模式，以及更复杂序列打包方案，仍未被论文充分验证。
4. **还缺什么证据**：缺少训练吞吐提升如何影响更新频率、召回新鲜度和长期业务指标的因果链，也缺少动态嵌入表、ID 去重、序列批处理与推理缓存、量化和 beam 搜索的组合实验。

## 研究问题变化

- **部分回答**：上周 P0/P1 中的 HSTU 和 Wukong 已完成论文卡初稿，说明它们不是孤立引用，而是两条独立的扩展路线。由于卡片状态仍为待复核，问题只能算部分回答，不能从 References 队列直接归档。
- **升级**：「SID 质量如何评估」需要加入稀疏-稠密混合路线。后续比较对象不只是不同 tokenizer，还包括稀疏 ID 条件化稠密生成、稠密检索外挂、端到端多模态表征和动态索引。
- **升级**：「推理成本如何控制」不应覆盖训练侧约束。应把训练吞吐、嵌入表动态性、ID 去重、序列负载均衡与推理 QPS、p99 延迟放在同一个扩展成本框架中。
- **保持开放**：「交叉特征与生成式架构如何兼得」仍没有统一答案。Wukong 证明稠密特征交互路线可以继续扩展，但没有证明它优于生成式序列转导；HSTU 又依赖序列化特征处理，二者缺少公平对照。
- **谨慎处理**：Hiformer 是排序特征交互证据，DeepSeekMoE 是语言模型证据。它们可以启发 MTmixAtt、TAE 等推荐架构的对比，但不应被当成生成式推荐的直接验证。

## 回流建议

- **知识卡片**：建议更新 [[Scaling Law在工业推荐系统的落地路径]]，把 HSTU、Wukong、RankMixer、TokenMixer 和 MTGenRec 分成「序列转导扩展」「稠密特征交互扩展」「硬件利用率」和「训练系统扩展」四类，并保留各自的实验口径和低算力/饱和边界。
- **知识卡片**：建议在 [[语义ID如何成为生成式推荐的基础设施]] 与 [[COBRA：稀疏ID引导稠密向量弥补生成式召回信息损失]] 中明确区分「纯离散 semantic ID」「稠密向量外挂」「稀疏 ID 条件化稠密生成」三种机制，避免把 COBRA 的单篇机制写成 SID 通用规律。
- **选题**：建议扩展 [[语义ID技术路线对比]]，在原证据表基础上加入 COBRA 和 LIGER 字段：稀疏 ID 结构、稠密向量训练方式、是否与生成过程耦合、召回资源、冷启动表现和公开复现条件。
- **输出**：[[语义ID技术路线对比]] 仍是优先级最高的候选输出；COBRA 让它更有价值，但也说明必须先处理单篇证据、会议版本和数据不一致问题。
- **归档**：本周不建议归档内容。Hiformer 和 DeepSeekMoE 虽然不是生成式推荐主线，但分别是 MTmixAtt 引用的特征交互和 MoE 方法来源，应保留为跨域方法参照。
- **下一轮体检**：检查 [[02_Knowledge/README.md]] 中新增论文卡是否接入现有表格和真实反向链接；同时核对 COBRA 卡中正文与表格数字差异、Hiformer 发表信息、MTGenRec 摘要与表 1 口径。
