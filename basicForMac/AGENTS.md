# Obsidian 个人知识库管理规则

本文件适用于当前知识库及其全部子目录。执行任何整理、写作或维护任务前，先读取本文件、相关笔记及上下文。目标是保持结构简单，明确区分原始资料、知识卡片、研究选题与输出成果。不确定时先说明，不强行处理。

知识库研究方向为「生成式推荐」，知识库迭代机制见 `06_Skills/规则/知识库如何从原始资料编译成研究资产.md`。所有资料按「证据层 → 编译层 → 研究层 → 输出层 → 体检层 → 回流」流转。

## 目录职责

- `00_Inbox`：信息入口。`自动抓取` 存放定时抓取内容，`手动剪藏` 存放网页剪藏、社媒内容和临时想法。中转站，保持清空。
- `01_Sources`：原始资料。`论文报告`、`行业新闻`、`会议纪要`、`旧资料导入`。剪藏和资料必须保留来源链接，不改写原文。
- `02_Knowledge`：知识卡片。`概念卡片`、`方法卡片`、`模型与案例`、`工具卡片`。用用户自己的话整理长期知识。
- `03_Topics`：选题与研究。`选题池`、`研究专题`、`问题清单`。
- `04_Outputs`：输出成果。`README.md` 是输出索引，`文章`、`报告`、`周报总结` 存放正式产出。
- `05_Review`：复盘迭代。`每日简报`、`每周复盘`、`月度总结`、`知识库优化记录`。
- `06_Skills`：技能包。`规则` 存放知识库迭代机制，`模板` 存放笔记模板。
- `99_Attachments`：附件素材。`图片`、`PDF`、`表格`、`视频素材`。
- `归档`：已完成、不活跃或被替代但不删除的内容。

AI 收集的新闻、摘要等未处理内容放入 `00_Inbox`，等待检查分类。AI 生成的初稿放入 `04_Outputs` 对应子文件夹，文件名加 `｜初稿`；经用户确认后去掉后缀成稿。不得把未经核对的 AI 内容表述为用户观点或最终结论。

每日简报以本地论文为底稿：从 `01_Sources/论文报告` 轮换一篇论文，解析 References，筛选近 5 年候选，再生成与生成式推荐相关的引文简读；Horizon 只负责把新闻和网页摘要放入 `00_Inbox/自动抓取`，不再直接作为每日简报正文。

## 笔记属性

新建或正式整理的 Markdown 笔记优先使用：

```yaml
---
创建日期: YYYY-MM-DD
更新日期: YYYY-MM-DD
类型: 笔记
标签: []
来源:
---
```

- 日期统一使用 `YYYY-MM-DD`。
- 不修改已有创建日期。
- 只有正文或核心属性发生实质变化时，才更新更新日期。
- 类型优先使用：`收藏`、`笔记`、`选题`、`文章`、`日记`、`复盘`。
- 不为格式完整而补充空话；不适合正式属性的临时文件可保持简单。

## Markdown 格式规范

AI 新建或整理的 Markdown 文件默认使用
`/Users/yangxiaochun/Documents/obsidian/obsidian-skills/skills/obsidian-markdown/SKILL.md`
统一格式，必要时同时读取同目录 `references/PROPERTIES.md`、`references/CALLOUTS.md` 和 `references/EMBEDS.md`。

- YAML frontmatter 必须合法，日期使用 `YYYY-MM-DD`，标签和列表使用 YAML 列表。
- 知识库内部链接使用 `[[wikilink]]`；外部网页、DOI、API 和仓库链接使用 `[文本](https://...)`。
- 标题、列表、表格、代码块使用标准 Markdown；重要提醒、数据风险和证据边界可用 `> [!warning]`、`> [!info]` 等 Obsidian callout。
- 格式化只调整语法、链接、属性和排版，不改变研究结论、数字、来源、状态或用户表达。
- 不使用「待补充」「TODO」「详见原文」这类占位符；信息不足时写明原因。
- 写入文件后做一次自检：frontmatter 可解析、表格和代码块完整、内部链接指向真实笔记或附件、外部链接格式正确。
- `01_Sources` 中的原始资料和用户手写内容不自动批量改写；确需格式化时先确认。

## 标签规则

- 根目录的 `标签索引.md` 是标签规范与用途的汇总；添加标签前先读取该文件，并扫描实际笔记中的 YAML 标签。
- 标签使用 YAML 列表，每篇通常保留 1～3 个主题标签；主题不清时留空。
- 添加标签前先扫描知识库中的已有标签，优先复用含义准确的已有标签，如 `生成式推荐`、`推荐系统`、`AI`。
- 如果现有标签不能准确表达主题，可以根据正文自动创建简洁、稳定的新主题标签，无需逐次征求确认。
- 标签表达主题，不使用 `收藏`、`有用`、`文章`、`笔记`、`稍后看` 等无主题标签。
- 创建新标签前检查同义词、近义词、不同语言写法和上下位关系，避免产生重复或过细的标签。
- 同义标签只保留一个规范写法。
- 新标签应直接反映正文的主要主题，不因为正文偶然提到某个概念就创建标签。
- 新建标签后，必须在同一次操作中把规范标签、适用范围、同义或停用写法和首次使用日期同步写入 `标签索引.md`。
- 普通新笔记只需在自身 YAML 中写入合适标签；如果使用的都是已有标签，不更新 `标签索引.md`。
- `标签索引.md` 只作为精简的标签词典，不记录关联文章、文章数量、反向链接或每次使用情况，避免随笔记增长而膨胀。
- 标签被改名、合并或停用时，同步更新 `标签索引.md`；批量修改仍须先提供影响范围并等待确认。
- 扫描发现实际笔记使用了索引中没有的新标签时，补充其词典条目；只有标签词典发生实质变化时才更新索引的更新日期。
- 批量修改标签前，先提供“旧标签 → 新标签”的对应关系及影响范围，等待确认。

## 文件命名

- 使用清楚、自然的中文标题，清理网站名、营销词和乱码。
- 避免使用“未命名”“新建笔记”“笔记1”等无意义名称。
- 新建或正式整理笔记时，先阅读正文并从核心事实、主要观点或共同趋势中提炼标题，不直接套用资料类别作为标题。
- 知识卡片使用“主题 + 核心观点”，例如 `生成式召回为什么适合冷启动场景`。
- 初稿或写作中的内容可添加 `｜初稿`、`｜写作中`。
- 日记命名为 `YYYY-MM-DD`；日期相关事件和新闻汇总命名为 `YYYY-MM-DD｜内容提炼标题`。
- 新闻汇总应概括当天最重要的事件或共同趋势，例如 `2026-07-17｜AI竞争转向系统入口、算力与监管`；不得使用 `AI科技新闻简报`、`每日新闻汇总`、`资料整理` 等泛化标题。
- 多主题内容优先提炼贯穿全文的共同线索；确实没有共同线索时，用最重要的两项主题组成简洁标题。
- 文件名不得包含 `\ / : * ? " < > |`。
- 重命名前检查内部链接。可能影响链接时，先提供“旧名称 → 新名称”预览，确认后执行。

## 资料整理与写作

处理资料时依次执行：

1. 判断内容性质。
2. 提取核心观点、关键例子、来源和待核实项。
3. 按检查规则评分，给出 S/A/B/C/D 分类建议。
4. 经确认后处理。

- `00_Inbox/手动剪藏` 和 `01_Sources` 中的原文保持原样，不覆盖、不擅自改写。
- 只建立真实相关的内部链接，不强行消灭孤立笔记。
- AI 生成的写作初稿放入 `04_Outputs` 并标注 `｜初稿`，核对后再成稿。
- 整理剪藏的产出需经确认后再执行。
- 新闻收集放入 `00_Inbox`，记录标题、日期、来源链接和简短摘要。
- 不覆盖或擅自改写用户的个人表达。

## 多文件操作与安全

所有多文件操作遵循：**扫描 → 预览 → 等待确认 → 执行 → 检查**。

以下操作必须先获得用户确认：

- 批量移动、重命名、修改属性或标签。
- 合并、覆盖或修改超过 10 个文件。
- 调整目录结构。
- 删除文件或附件。
- 修改 `.obsidian`。

默认不永久删除内容。需要移除时，优先移入 `归档` 并说明原因。若目标或链接影响不明确，停止操作并向用户说明。

## 日常任务的输出要求

- 整理文件夹前，先提供包含“原文件、建议名称、目标文件夹、标签、理由”的处理清单。
- 加标签时先复用已有标签；没有合适标签时，自动创建并写入通常 1～3 个准确的主题标签。
- 执行前读取相关内容和上下文。
- 完成后简要说明修改了哪些文件，以及仍需用户确认的事项。
- 检查重复文件和失效链接时，先报告检测依据，不直接删除或改链。
