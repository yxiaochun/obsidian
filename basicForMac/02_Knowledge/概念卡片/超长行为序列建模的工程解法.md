# 超长行为序列建模的工程解法

长序列是推荐 scaling 中收益最确定的维度之一，但撞上两堵墙：注意力二次方复杂度、海量历史的存储与检索 I/O。

## 算法侧方案

- [[LONGER：全局token稳定超长行为序列建模]]：全局 token 稳定长上下文注意力。
- [[MakeItLongKeepItFast：万级序列的线性复杂度建模]]：STCA 目标-历史交叉注意力（二次方→线性）+ 请求级 batch 共享用户编码 + 短训长推的长度外推。
- [[LASER：分段目标注意力突破长序列延迟墙]]：兴趣稀疏性出发，sigmoid 门控过滤噪声 item，分段压缩后再做全局堆叠注意力。

## 系统侧方案

- SeqVault（LASER）：DRAM-SSD 混合索引，检索时延 -50%、CPU -75%。
- 跨请求 KV 缓存（[[OneTrans：一个Transformer统一特征交互与序列建模]]）：用户侧表示预计算复用。
- [[UGSep：用户侧计算复用降低大模型推理成本]]：稠密交互模型里隔离用户侧信息流实现 compute once。

## 规律

落地成功的方案都是算法-系统协同设计：单靠换注意力算子或单靠加机器都过不了延迟墙；长度外推让训练成本与推理长度解耦是重要的杠杆。
